## Polling이란?

**클라이언트가 일정한 주기로 서버에 계속 요청을 보내서 상태 변화를 확인하는 방식**

> “바뀐 거 있어요?”
> “아직이요”
> (n초 후)
> “이제 바뀌었어요!”

대표 예:

* 알림 개수 확인
* 배치 작업 진행 상태 조회
* 결제/업로드 완료 여부 체크

```ts
setInterval(() => {
  fetch('/api/status')
    .then(res => res.json())
    .then(console.log);
}, 5000); // 5초마다 요청
```

* 주식 창에서 7초마다 polling을 보내서 데이터를 최신화 해주는 모습
![polling](assets/polling.gif "주식 창에서 7초마다 polling을 보내서 데이터를 최신화 해주는 모습")

## Polling의 종류

### 1️⃣ 일반 Polling

* **고정 주기**로 계속 요청
* 가장 단순

### 2️⃣ Long Polling

* 서버가 **변경될 때까지 응답을 보류**
* 응답 오면 즉시 다시 요청
* 실시간처럼 보이지만 사실은 polling

---

## 장점 👍

### 1. 구현이 매우 쉽다

* HTTP만 있으면 됨
* WebSocket, SSE 같은 별도 프로토콜 불필요
* 방화벽/프록시 이슈 거의 없음

### 2. 서버 구조가 단순

* 기존 REST API 그대로 사용 가능
* 상태 조회용 API 하나면 끝

### 3. 예측 가능

* 트래픽 패턴이 명확
* 장애 시 디버깅 쉬움

> 특히 **사내 B2B, 관리자 페이지**에 잘 맞음

---

## 단점 👎

### 1. 불필요한 트래픽 발생

* 변경 없어도 계속 요청
* 사용자 수 많아지면 서버 부담 급증

### 2. 실시간성이 떨어짐

* 주기가 5초면 최대 5초 지연
* 줄이면 → 서버 터짐 😇

### 3. 리소스 낭비

* 모바일 환경에서 배터리 소모
* 서버 CPU, 네트워크 낭비

### 4. 스케일에 취약

* 사용자 × 주기 = 요청 폭발
* “처음엔 잘 되는데 나중에 느려짐”의 대표 사례

## Polling vs 다른 방식 간단 비교

| 방식           | 실시간성 | 서버 부하 | 구현 난이도 |
| ------------ | ---- | ----- | ------ |
| Polling      | ❌    | ❌     | ⭐      |
| Long Polling | ⭕    | △     | ⭐⭐     |
| SSE          | ⭕    | ⭕     | ⭐⭐     |
| WebSocket    | ⭕⭕   | ⭕⭕    | ⭐⭐⭐    |

---

## 언제 Polling을 쓰면 좋을까?

✅ **변경 빈도가 낮을 때**
✅ **실시간이 꼭 필요 없을 때**
✅ **관리자/백오피스 화면**
✅ **배치·비동기 작업 상태 조회**

> 예: “결제 완료됐는지”, “리포트 생성 끝났는지”

## 프론트 개발자 시점 꿀팁 💡

* `setInterval` 남발 ❌
  → **페이지 visible일 때만**
* **백오프 전략** (점점 주기 늘리기)
* React라면

  * `useEffect + clearInterval`
  * 또는 **React Query의 refetchInterval** 활용
